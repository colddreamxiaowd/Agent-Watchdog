# Agent Watchdog — v2 产品需求与阶段门槛

> AW-V2-ROUND1-21-24；依据用户提供的《Agent Watchdog 修订计划与跨会话交接 v2.0》。这是需求与证据契约，不是功能已全部完成的声明。

## 产品目标

Agent Watchdog 是运行在用户电脑上的**独立、只读、只提醒**的 AI Agent 监督程序。首要目标 Codex CLI；未来可扩展其他 Agent。监督对象包括：(1) 已观察到的工具启动、完成及结构化结果，(2) 与用户批准目标相符的真实进展，(3) 超时、反复失败、事件断流，(4) 范围约束与疑似目标偏离，(5) Agent 声称完成时的独立验收，(6) 带依据和可行动建议的提醒。

第一版不得自动杀掉进程、重试有副作用工具、回滚文件、代替人授权、修改 Codex 数据库，也不得因为少了事件就声称卡死。

## 不可偷换的证据分层

- `TUTORIAL_WRITTEN`：仅证明文章存在。
- `REFERENCE_CODE_TESTED`：以固定代码、测试环境、真实测试报告为证，只证明这些测试场景。
- `REAL_CODEX_E2E_VERIFIED`：用户机器上，经审核的可信 Hook 与一次真实工具操作能人工匹配。
- `DETECTOR_EVALUATED`：经许可的真实轨迹有人标注，有误报、漏报、延迟、不可判定分母。
- `RELEASE_READY`：G0–G4 通过、恢复与隐私安全审核可核查。
- `RELEASED`：用户批准实际发行；教程写完不算 Release。

## 阶段门槛

| Gate | 决定条件 | 本轮约束 |
|---|---|---|
| G0 | 当前仓库 HEAD、Python/Git/可用 Codex 版本、完整基线测试及失败原因 | GitHub Actions Windows/Linux 是托管 Runner，**不是用户真机** |
| G1 | 用户电脑在可控测试仓库从 `/hooks` 可信配置看到真实事件与独立 Git 观察 | 若无法访问 Windows，`NOT_VERIFIED` |
| G2 | 工具启动/结束能够按稳定操作 ID 关联，缺少结果不伪造 PASS | 统一事件 schema，source 标识不作身份认证 |
| G3 | 人工标注真实对照样本，事先约定阈值，报告误报/漏报/不可判定 | 没有这些样本，异常提示只能称为未校准启发式 |
| G4 | Windows 多会话、休眠、重启、通知冷却、备份恢复与安全审查 | 第 21–24 篇不声称通过 |

## 数据最小化与信任

`tool_input`、`tool_response` 正文、用户提示、完整命令和系统环境变量默认**不落库、不入公网**。采集仅包括来源标签、观测时间、会话/回合/工具调用标识、工具种类、可选路径、严格提取的数值退出码等。路径与会话 ID 仍属私密元数据，日志与 SQLite 只能保存在本地并设置访问控制。来源字段 `hook_input_unverified` / `codex_exec_export_unverified` / `app_server_export_unverified` 都不具备密码学认证能力。

## 架构与职责

`execution_v2.py` 只做脱敏投影；`journal.py` 负责 SQLite 去重和断点续导；`runtime_v2.py` 只从脱敏记录输出可解释风险；`step_links_v2.py` 负责经批准合同之下的**人工关联**，再读取 `task_contract.py` 的独立测试验收，绝不把关联本身当完成。`doctor_v21.py` 只做本机就绪度检查，永远不自行认证真实 Hook。

范围、截止日期、任务语义由人批准的合同控制；语义偏离检测是第 27 篇待评估问题，不是本轮成果。

## 第 25–28 篇的前置条件

建议可开展低风险的下一轮研究、离线标注工具与参考实现；**不能**在没有 G1 现场结果与 G3 真案例前宣布智能监督器已可用。第 25 篇的重复失败判别要引入真正有权限的结构化操作身份和结果；第 26 篇 StepWise 必须和不用模型的基线比较；第 27、28 篇必须接受未知、不充分与人工介入。
